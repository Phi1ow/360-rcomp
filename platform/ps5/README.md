## 1. How PS5_RetroArch builds a title (audit of @18dc1059c497)

A *payload* (what `ps5-payload-sdk` produces by default: `prospero-clang` links
`crt1.o`, static `libc.a`, `-lkernel_web -lSceLibcInternal -lSceNet`, with the
SDK script `ldscripts/elf_x86_64.x` whose text segment is **RWX**) is an ELF
injected into an existing process by an ELF loader. A *title* is a
`/data/homebrew/<TITLE_ID>/` folder the system launches as an application with
its own process, budgets and `/app0` mount. PS5_RetroArch uses the pipeline of
BlackBearReloaded's ps5-native-app-boilerplate (`tools/build.sh`,
`tooling/native/`, GPL-3.0):

1. Compile with the SDK compiler for `-target x86_64-sie-ps5` plus
   `-fvisibility-nodllstorageclass=default -fno-stack-protector -fno-plt
   -femulated-tls` and the SDK sysroot (`tooling/prospero-clang18`; the SDK's own
   `bin/prospero-clang{,++}` add the same flags). App code: `-std=c++20 -O2
   -ffunction-sections -fdata-sections -fno-exceptions -fno-rtti`.
2. Own CRT (`tooling/native/app_crt.cpp`): entry `_start(params, teardown)`;
   `argc` at `params+0`, `argv` at `params+8`; **zeroes .bss itself** (the
   console loader does not, FINDINGS: a static read garbage); calls
   libSceLibcInternal's `_init_env(params)`, registers `teardown` and fini with
   `atexit`, runs preinit/init arrays, `exit(main())`. A tiny `operator
   new/delete` bridge replaces libc++abi when exceptions/RTTI are off.
3. `prospero-lld -T ps5-pie.ld --eh-frame-hdr --version-script ...
   --exclude-libs=ALL -e _start ... --as-needed <sdk>/target/lib/*.so`. The
   script separates R-X text at VA 0, R rodata/eh_frame, RELRO (.got, .dynsym,
   init arrays) and RW data starting with `.dynamic`; it defines
   `__eh_frame{,_hdr}_{start,end}` because the SDK `libunwind.a` needs them (no
   `dl_iterate_phdr` in a title). C++ with exceptions links the SDK's static
   `libc++.a libc++abi.a libunwind.a` (+ compiler-rt builtins).
4. `ps5-native-tool link`: rewrites the LLVM PIE into a PS5 dynamic executable
   (ELF e_type 0xFE10, OS/ABI FreeBSD, SCE dynamic sections, imports bound to SDK stub
   sonames/NIDs, process parameters written between RELRO and data), with
   loader constants `--module-sdk 0x02000009 --companion-sdk 0x08050001`
   ("validated on firmware 6.02 and 12.70" in their build.sh). It refuses any
   exported symbol.
5. `ps5-native-tool self --sign --magic 0x1D3D154F` -> fake-signed `eboot.bin`
   ("an unsigned eboot.bin is a title that fails to start with no message").
6. Folder: `eboot.bin`, `sce_sys/param.json` (+ `icon0.png` 512x512 PNG
   mandatory in their validator; `pic0/pic1.dds`, `snd0.at9` optional),
   `sce_module/libc.prx` (a clean-room runtime module generated by
   `tooling/native/libc_builder.cpp` from two text manifests, sha256
   `e6ff45d1...0036`).
7. Optional images: `.ffpkg` (UFS2Tool, .NET 8, github SvenGDK/UFS2Tool) and
   `.ffpfsc` (MkPFS, Python, github PSBrew/MkPFS). Deployment in their loop is the
   plain folder over FTP to `/data/homebrew/<TITLE_ID>/`, launched by a resident
   control payload (PS5_Vulkan `payload/ps5vkctl`: `procs`, `launch`, `kill`).

Other measured constraints worth keeping: a title cannot `dlopen` a linked
`.so` (sceKernelLoadStartModule ENOEXEC) - link statically; libc++'s
`std::filesystem` hits unsupported `opendir/openat` (they `--wrap` them);
`__BIGGEST_ALIGNMENT__` is 32 (AVX stores into `new` objects need 32-byte
alignment); SceLibcInternal's private heap for <1 MiB allocations is small
and ran out long before the process did.

**Availability here:** everything for a folder title is obtainable from public
sources already pinned (SDK v0.42 + PS5_RetroArch tooling source). Verified in
this environment: the tools build with host clang++ 18 + system zlib and
`libc.prx` reproduces bit-exact (raw `8ee6e124...02bb`, signed
`e6ff45d1...0036`). The only obstacle is licensing (GPL-3.0 host tools and a
GPL-3.0 runtime module shipped in the folder), hence the explicit opt-in.
`.ffpkg`/`.ffpfsc` tools are not pinned or fetched (network + .NET): BLOCKED,
not required.

### Our title build (platform/ps5/tools/build_title.sh)

Own code, written from the constraints above, no copy: `title/crt/rcomp_title_crt.cpp`
(entry, BSS clear with `rep stosb`, `_init_env`, init/fini arrays),
`title/crt/rcomp_title.ld` (same segment contract, no W+X segment - the script
checks), `title/crt/rcomp_title_symbols.map` (export nothing). Imports are
bound to `libSceLibcInternal.so` and `libkernel.so` explicitly (not a
glob). Not `libkernel_web.so`: a title process only loads `libkernel.sprx`, so
imports bound to `libkernel_web` stay NULL (PS5 run of kit f414844: tests 1, 2,
3 and 8 jumped to 0 at their first `getpid`; see `docs/PS5_RESULTS.md`). The
build refuses an `eboot.elf` that still names `libkernel_web`. Steps 4-6 call the GPL tools compiled into `build/platform-ps5-tools/`
from the pinned, unmodified checkout (pin and cleanliness are checked).

**Emulated TLS:** the SDK compilers force `-femulated-tls`; `thread_local`
references `__emutls_get_address`, which no SDK stub exports and this host has
no compiler-rt builtins archive for. Runtime/generated code must avoid
`thread_local` until compiler-rt builtins are provided (open item).

## 2. Title ID

Format `PPSA` + 5 digits; `contentId` = `XXdddd-<titleId>_00-<16 [A-Z0-9]>`;
`conceptId` 5 digits. IDs found in the reference trees: PPSA99169 (RetroArch),
99005, 99988, 99999 (refused by ps5vkctl as "default profile"), 99002, 99006,
99010, 99611, 99989-99998, 12345/12346/54321 (examples). Retail IDs are far
below 9xxxx. Chosen: **PPSA88360** ("88" + "360"), content id
`UP9000-PPSA88360_00-RCOMPTEST0000001`: absent from both reference trees and
outside the 999xx homebrew cluster. Only one title runs at a time; launching
while another runs is refused with 0x80940010 (PS5_RetroArch console-run.sh).

## 3. Memory on the PS5

Terms: **VA reservation** = address range owned, no backing, no budget
charged (only when made with the right primitive); **committed** = mapped with
backing; **physical** = RAM actually consumed; **flexible memory** = the
per-title pool that backs anonymous `mmap`/heap/stacks/JIT; **direct memory** =
a separate physical pool allocated explicitly (offset handle) and mapped at any
VA, also what GPU-visible memory is.

| Primitive (all exported by SDK libkernel stubs, none declared in headers) | Evidence |
| --- | --- |
| POSIX `mmap/mprotect/munmap` (anonymous) | charged to flexible memory, **including PROT_NONE reservations** (PPSSPP_Implementation_Plan.md s.5; Dolphin patch: a PROT_NONE arena "is charged to the title's small flexible-memory budget and fails") |
| `sceKernelReserveVirtualRange(&addr,len,flags,align)` | 4 GiB succeeds, 64 GiB fails 0x8002000C (PPSSPP_Core_Plan.md s.5); used by the Dolphin port at 0x10_0000_0000 with MAP_FIXED re-reservation of holes |
| `sceKernelAllocateDirectMemory` + `sceKernelMapDirectMemory` | pool 12,288 MiB reported; 4 GiB allocated, mapped, written, released; type 12 for CPU heaps; mapped MAP_FIXED into a reservation by the Dolphin port |
| `sceKernelMapFlexibleMemory` | exported; draws on the same ~448 MiB pool - no benefit for guest RAM |
| `sceKernelMprotect` | direct-memory protection change works (execute needs mprotect, never map-time RWX) |
| `sceKernelAvailableFlexibleMemorySize` | 448 MiB configured, 442 MiB available at start; about 432 MiB anonymous allocations before ENOMEM |

Other facts: page size **16 KiB**; `mprotect` rounds an unaligned address
instead of failing; a page-table accounting allowance of 16,384 entries is
reported (semantics unknown); the kernel **refuses** a placement hint it cannot
honour rather than relocating; **GPU window**: PS5_Vulkan requires every
GPU-visible mapping in [0x2_0000_0000, 0x3_0000_0000) (its shader compiler uses
high word 2) and unhinted reservations/JIT mappings landed there in the
PPSSPP/Dolphin ports; libkernel modules sit near 0x8_0000_0000.

**Decision: `os_vm_posix.cpp` is not valid on the PS5** (4 GiB + 64 KiB of
PROT_NONE anonymous mapping would be charged to ~448 MiB of flexible memory;
FreeBSD has no `MAP_NORESERVE` - the bit is `MAP_RESERVED0040` in the SDK's
`sys/mman.h`, so the posix file's `#ifdef` silently drops it). The PS5 build
uses **`os_vm_ps5.cpp`**:

- reserve: `sceKernelReserveVirtualRange`, 64 KiB aligned, hints
  0x10_0000_0000, 0x18_0000_0000, 0x20_0000_0000, 0x4_0000_0000, then kernel
  choice; any result overlapping the GPU window is released and rejected.
- commit: per run of unbacked 64 KiB pages, one direct allocation (type 12,
  CPU RW) mapped MAP_FIXED over the reservation, zero-filled by us, then
  `sceKernelMprotect` to the requested protection; backed pages are kept
  (contents preserved); failures unwind only the pages this call backed.
- decommit: `sceKernelMunmap`, re-reserve the hole with MAP_FIXED, release the
  direct memory. release: decommit all, unmap the reservation.
- Physical cost = committed bytes only, from the 12 GiB direct pool; flexible
  cost = 512 KiB tracking table. Guest memory is never GPU-visible nor executable.
- 2 MiB pages were tried and not kept (journal phases 95-96, `docs/PERF_4K30_20260929.md`): the part of a commit run
  that covers whole 2 MiB blocks was allocated and mapped with 2 MiB alignment on the virtual address and the
  direct-memory offset (16 segments, 434 MiB at start-up, no fallback, the guest heap committing whole runs instead
  of page by page); the frame rate did not move (+0.3 %, inside the noise). The experiment is the patch
  `docs/evidence/wave3-20261001/p1-large-pages.patch`; whether the kernel uses 2 MiB entries stays NOT TESTED.

`GuestMemory::is_accessible` checks every touched 64 KiB page for Read or
ReadWrite access, using two additional 8 KiB permission bitmaps. Successful
commit/protect/decommit operations update them; failed operations leave them
unchanged. Runtime-owned ranges are promoted to ReadWrite before ownership is
recorded. Callers serialize mapping changes: this query does not pin pages
against concurrent protection changes. `translate` retains its committed-only
contract, so HLE code that reads or writes guest pointers must also check the
required access. Host tests exercise real protection transitions and inject
failures before VM mutation; they do not prove rollback of partially completed
PS5 kernel operations.

Assumptions (NOT TESTED; the self-test title checks each of them):
A1 `sceKernelMapDirectMemory(MAP_FIXED)` over our own reservation replaces it
(Dolphin did this; not with our sizes). A2 `sceKernelReleaseDirectMemory` accepts
a sub-range of one allocation (needed when a decommit splits a run;
`os::ps5::set_max_run_bytes(64 KiB)` removes this dependency). A3 access to a
reserved-but-unbacked page raises SIGSEGV/SIGBUS (guard and decommit tests).
A4 hint 0x10_0000_0000 is free in a title process. A5 recycled direct memory is
not guaranteed zero (we memset; cost ~ commit size). A6 many small commits may
hit the 16,384-entry allowance - guest allocators should commit in large runs.
A7 memory type 12 is appropriate for CPU-only memory (both references use it;
PS5_Vulkan also maps it GPU-visible).

## 4. CPU and ISA flags

`prospero-clang -###` shows `-target-cpu znver2` by default (macros
`__AVX2__ __FMA__ __BMI2__ __F16C__ __LZCNT__ __MOVBE__ __SSE4A__
__tune_znver2__`). `-march=x86-64-v3` (AVX, AVX2, BMI1/2, F16C, FMA, LZCNT,
MOVBE, XSAVE + v2) is a strict subset of Zen 2: **no objection**, it lets the
same generated code run on x86-64-v3 hosts for oracle tests. Additions:
`-mtune=znver2` (x86-64-v3 alone implies generic tuning); note BMI2
`pdep/pext` are microcoded and very slow on Zen 2 - do not emit them by
intrinsic in the prelude. `-ffp-contract=on` is clang's C/C++ default already;
checked on the PS5 target: `a*b+c` in one expression -> `vfmadd213sd`, the same
split across two statements -> `vmulsd`+`vaddsd` (PPC separate rounding kept).
`cmake/toolchains/ps5.cmake` exposes `RCOMP_GENERATED_ISA_FLAGS`,
`RCOMP_GENERATED_FP_FLAGS`, `RCOMP_GENERATED_CODE_FLAGS` (per-target use) and
rejects anything containing `native`.

CPU corpus mode (M2): after `ninja -C build/tests-cpu-ps5` (tests/ owns that
build), `build_title.sh --cpu-corpus` (or `RCOMP_TITLE_CPU_CORPUS=1`) links
`librcomp_cpu_selftest.a` + `librcomp_cpu_generated.a` into a title under
`build/platform-ps5-title-cpu/`; `main` then calls `rcomp_cpu_selftest(log, start)`
after the platform self-test and logs `RCOMP-TITLE cpu begin start=<n>` /
`RCOMP-TITLE cpu status=<n>` around the harness's JSON lines. `start` comes from
`/app0/rcomp_cpu_start.txt` (uploaded by `run_title.sh --cpu-corpus` when
`RCOMP_CPU_START` is set) so a run that crashed (harness writes a `"signal N"`
FAIL line and `_exit(3)`s) can be resumed; `collect_cpu_results.py LOG... --out
x.jsonl [--meta m.json]` merges the last run of each fetched log.

The title (`title/main.cpp`) runs the same suite as the host tests
(`tests/test_guest_memory.cpp`, fault checks via `sigsetjmp` because a title
cannot fork), prints flexible/direct budgets before and after, appends to
`/app0/rcomp_title.log` (= `/data/homebrew/PPSA88360/rcomp_title.log` over FTP)
and exits 0/1/2. `run_title.sh` uploads + reads back, captures klog before
launch, polls `procs`, on timeout sends `kill PPSA88360` only if `procs`
reports that title, downloads the log and judges the last `RCOMP-TITLE end`
line.

## 6. Licences

Nothing from PS5_RetroArch or PS5_Vulkan (GPL-3.0) is copied into this tree.
`ps5_kernel.h` restates function prototypes and numeric constants (ABI facts)
observed in them, with provenance. The CRT, linker script, os_vm backend,
tests and scripts are written for R-comp. The optional title steps *execute*
GPL-3.0 host tools built from the pinned checkout and ship the GPL-3.0
`libc.prx` in the title folder; the SDK itself is GPL-3.0 wrappers + bundled
libraries. PRIME decides whether that is acceptable (`RCOMP_ACCEPT_GPL_TITLE_TOOLS`).
